\begin{abstract}
\noindent
\textbf{本文报告同一项目下的两个并列任务}：判别式（音乐流派分类）与生成式（离散 Token 预测与
音频续写）。二者使用同一份数据划分与同一条实验纪律，但前端与指标完全不同。

\textbf{任务一，判别式。}音乐流派分类是音乐信息检索的经典任务，也是检验不同建模范式的天然
试验台。本文在\emph{同一套数据划分与同一套评估协议}下，系统比较了六类模型：基于人工特征的 SVM 与 MLP、端到端 CNN、CNN+BiGRU（CRNN）、轻量 Transformer，以及冻结 AudioSet 预训练主干的 Audio Spectrogram Transformer（AST）。实验覆盖两个数据集：清洗后的 GTZAN（985 首、10 流派，作为最小可行 MVP）与 FMA-small 主实验（8\,000 首、8 流派）。所有深度模型使用 3 个随机种子重复训练，测试集只在模型冻结后评估一次，并启用了 cuDNN 确定性以保证可复现。\input{numbers_abstract}
本文进一步给出错误分析、七种扰动下的鲁棒性实验、片段级时间轴分析，以及面向 CNN/CRNN/Transformer 的 SpecAugment 与标签平滑优化消融。结果显示：预训练表示带来最大的单点收益，但在噪声与短片段下所有模型的可靠性都显著下降；深度模型赢在干净输入，传统模型在输入变脏时反而更稳。
\textbf{任务二，生成式。}后者把预测目标从流派标签换成\textbf{离散 Token 序列}——用 EnCodec 把音频量化成 50\,Hz、4 码本的 Token，比较 LSTM 与小 Transformer 对下 1 秒 Token 的预测能力，并评估 MusicGen-small 的前缀续写与 LoRA 适配。该部分记录了一次\textbf{被修正的负结果}：初版 LoRA 适配因标签维度错误而完全无效（目标值停在均匀分布之上），修正后音频距离从 19.23 降到 17.91，且 8 首中 7 首改善——说明"训不动"未必是容量或数据不足，也可能只是目标对齐写错了。
代码、权重生成脚本与全部结果文件均已开源。
\vspace{0.3em}\\
\textbf{关键词：}音乐流派分类；离散音频 Token；音乐生成；EnCodec；LoRA；GTZAN；FMA-small；可复现实验
\end{abstract}

\section{引言}

\subsection{研究背景}

音乐流派（genre）是人类对音乐风格的一种高层概括，广泛用于推荐、检索、曲库管理与版权结算。自动流派分类要求模型从波形中提取音色、节奏、和声与配器等线索，是连接信号处理与音乐理解的典型任务\cite{tzanetakis2002gtzan,casey2008content}。在流媒体平台上，每天有大量新曲目缺少人工标注，自动流派标签能显著降低冷启动成本；在音乐教育中，流派分类也可以作为理解音色与节奏的入口。

过去十余年，该任务的建模路线经历了三次明显的迁移：从人工特征加浅层分类器，到端到端卷积网络\cite{choi2017crnn,dieleman2014endtoend}，再到自注意力\cite{vaswani2017attention}与大规模预训练模型\cite{gong2021ast,kong2020panns}。每一次迁移都伴随新的问题：深度模型是否真的优于精心设计的人工特征？预训练带来的收益有多少来自数据、多少来自架构？在资源受限的课堂上，我们能否得到可信、可复现的结论？

与分类这条线并行的，是近三年兴起的\textbf{生成式}路线。其关键一步是把连续波形离散化：
神经音频编解码器（SoundStream、EnCodec\cite{defossez2023encodec}）用残差向量量化把音频压成
每秒几十帧、每帧若干个码本的离散 Token。一旦音频变成 Token 序列，"下一个 Token 是什么"
就成为一个可以用交叉熵直接度量的语言建模问题——AudioLM\cite{borsos2023audiolm} 据此做音频续写，
MusicGen\cite{copet2023musicgen} 进一步把文本条件接进来，成为可控的音乐生成模型。
这条路线带来一个诱人的猜想：如果同一个系统既能把音频压成 Token，又能预测 Token，
那么"理解音乐"与"生成音乐"或许是同一件事的两面。

本文因此在流派分类之外，用\textbf{同一批数据与同样严格的划分纪律}再做一个生成式任务：
在离散 Token 层面预测真实未来、把预测解码回音频、并评估预训练生成模型的前缀续写。
两个任务并列，而不是把生成当作分类的附属演示。

\subsection{问题与挑战}

文献中的准确率数字往往不可直接比较，原因至少包括：
\begin{enumerate}
  \item \textbf{数据划分不一致}：同一数据集的不同版本、不同随机划分，甚至测试集被反复用于调参；
  \item \textbf{片段与预处理不一致}：3 秒 / 5 秒 / 10 秒片段、采样率、归一化方式都会改变输入分布；
  \item \textbf{标签本身模糊}：「Rock」与「Metal」、「Pop」与「Dance」的边界在人类标注者之间也不一致；
  \item \textbf{数据泄漏隐蔽}：同一曲目的不同片段、同一艺术家的不同作品跨集合，都会让模型「记住来源」而不是学习风格；
  \item \textbf{计算预算差异}：预训练模型的权重体积与推理延迟比自建模型高两到三个数量级。
\end{enumerate}
因此，一个负责任的判别式基准必须同时报告\emph{协议、成本与失败模式}，而不只是一个准确率。

生成式任务另有一类更根本的困难。分类有明确标签可以对齐，而"这段前缀之后应当是什么"本身
是开放集合：用与真实后续的距离（Log-Mel RMSE 或 FAD\cite{kilgour2019fad}）度量，只能说明
"接近真实"而非"好听"；主观评分又难以规模化。因此生成实验必须把\textbf{可度量的部分}
（Token 级 NLL、Top-1）与\textbf{只能定性判断的部分}（音乐性）分开报告。
叠加在评价困难之上的是资源约束：8\,GB 显存既要装下 300\,M 的生成模型，又要留出适配的
优化器状态，可用的手段本来就不多。这两条共同决定了任务二能做到哪一步。

\subsection{研究问题}

本文围绕五个问题展开，前三个属判别式任务，后两个属生成式任务：
\begin{enumerate}
  \item 在完全相同的协议下，不同代际的模型（传统 ML、CNN、CRNN、Transformer、预训练 AST）差距究竟有多大？
  \item 数据规模从千首级（GTZAN）扩大到万首级（FMA-small）时，结论是否稳定？
  \item 常见优化手段（SpecAugment、标签平滑、dropout）能带来多少真实收益，代价是什么？
  \item （生成式）把目标从流派标签换成离散 Token 序列后，同一套评估纪律能得到什么？
        小容量模型对下 1 秒 Token 的预测能力上限在哪里？
  \item （生成式）8\,GB 显存的课堂上，预训练生成模型的前缀续写与轻量适配各自能做到哪一步，
        失败的边界又在哪里？
\end{enumerate}

\subsection{主要贡献}

本文的主要贡献如下：
\begin{itemize}
  \item \textbf{统一基准}：在同一套按曲目 / 按艺术家划分与同一套评估协议下比较六个代表性模型，两条前端（5 秒频谱 vs 6 秒 Token）的差异在第~\ref{sec:frontend} 节交代；
  \item \textbf{泄漏诊断}：量化了 FMA-small 上「按曲目划分」带来的艺术家级泄漏，并用对照实验证明其会把 CNN 的 Macro-F1 虚高约 9.9 个百分点；
  \item \textbf{优化消融}：系统尝试 SpecAugment、标签平滑与 dropout，报告了一个诚实的负结果——在 FMA 上最大提升仅 0.7 个百分点；
  \item \textbf{行为分析}：给出错误分析、七种扰动的鲁棒性、片段级时间轴与置信度校准，说明准确率之外的模型差异；
  \item \textbf{可复现交付}：公开代码、配置、结果文件与 LaTeX 报告，所有数字可由脚本重新生成，且经过独立只读审计。
  \item \textbf{生成式任务基准}：用 EnCodec 把音频量化为 $4\times300$ Token，在同一份
        按艺术家分离的划分上比较 Persistence、频率先验、Bigram 与两种神经模型（LSTM、
        小 Transformer），并\textbf{分别}报告 teacher-forced 与 free-running 两种口径，
        避免用前者冒充后者。
  \item \textbf{一次被修正的负结果}：预训练生成模型的 LoRA 适配初版完全无效。我们用
        未训练模型的目标值对照（错误布局 11.08 / 正确布局 5.46 / 均匀分布 7.62）定位到
        标签维度错误，修正后音频距离由 19.23 降到 17.91 且 8 首中 7 首改善；而随后
        对训练步数、目标窗口、适配秩三个旋钮的配对检验\textbf{均不显著}。
  \item \textbf{负结果的辨别方法}：本文给出三件在报告中容易被忽略的检验——逐曲配对检验
        （排除"单首拉低均值"）、去掉最优样本后的复核、以及按几何衰减外推判断"最优轮次
        撞上限"是否真的意味着欠训练。三者都曾改变本文的结论。
\end{itemize}

\section{相关工作}\label{sec:related}

本章按三条线组织：第~\ref{sec:rw-mir}--\ref{sec:rw-e2e} 节回顾判别式任务所依赖的世代线
（人工特征、端到端深度模型、预训练 Transformer）；第~\ref{sec:rw-token}--\ref{sec:rw-lora} 节
回顾生成式任务的技术链（音频 Token 化、自回归生成、参数高效适配）；第~\ref{sec:rw-eval} 与
第~\ref{sec:rw-robust} 节讨论两个任务共用的数据、评测与可复现问题。
两条线在模型层面几乎没有交集——判别式任务输出类别，生成式任务输出 Token 序列——
因此本章不合并叙述，只在共用部分（数据来源、评测口径、复现纪律）收拢。

\subsection{音乐信息检索与流派分类}\label{sec:rw-mir}

音乐信息检索（Music Information Retrieval, MIR）关注从音频、乐谱、歌词或元数据中提取结构化
信息\cite{downie2003mir,casey2008content}，任务族包括标注、检索、分离、转录与近年的生成。
流派分类是其中最早被系统研究的任务之一：Tzanetakis 与 Cook 在 2002 年提出用谱特征、节奏特征
与梅尔倒谱系数训练分类器，并发布了 GTZAN 数据集\cite{tzanetakis2002gtzan}。它之所以长期充当
试验台，是因为标签现成、类别均衡、评价口径统一——换句话说，它把「表示好不好」这个问题从
「标注贵不贵」里剥离了出来。本文把它作为判别式任务的载体，正是看中这一点。

\subsection{人工特征与浅层模型}

传统方法通常把音频切帧，逐帧计算 MFCC、谱质心、谱带宽、rolloff、过零率、chroma 与节奏直方图，
再在时间维做统计池化，最后送入 SVM、随机森林或 k 近邻\cite{tzanetakis2002gtzan,bogdanov2013essentia}。
这类方法有两个优点：一是计算便宜，二是特征具有明确的声学含义。其局限在于统计池化会丢失时间结构，
且特征设计依赖领域知识。

\subsection{端到端深度模型}\label{sec:rw-e2e}

随着数据规模与算力增长，端到端学习逐渐取代人工特征。Dieleman 与 Schrauwen 直接把波形送入
CNN\cite{dieleman2014endtoend}；Choi 等提出 CRNN，用卷积层提取局部时频模式、用循环层建模时间
演化\cite{choi2017crnn}；Humphrey 等系统比较了特征学习与手工特征\cite{humphrey2013feature}。
在音频事件识别领域，Hershey 等比较了多种 CNN 架构\cite{hershey2017cnn}，PANNs 则用大规模预训练
提升通用性\cite{kong2020panns}。这些工作共同确立了一个经验：数据规模决定端到端方法能否赢过
人工特征，而在万首量级以下的语料上，两者的差距会显著收窄。

\subsection{神经音频编解码与离散 Token}\label{sec:rw-token}

生成式任务的起点是一个表示问题：语言模型只吃离散序列，而音乐是连续波形。SoundStream 与
EnCodec\cite{zeghidour2021soundstream,defossez2023encodec} 用残差向量量化（RVQ）把音频压成
低帧率的码本序列：编码器逐级量化残差，每一级产生一个码本索引，于是同一段音频被表示为若干条
并行的 Token 流。EnCodec 在 32\,kHz 上以 50\,Hz 输出 4 个码本、每个码本 2048 个词表项，
码率约 2.2\,kbps，解码后的听感仍接近原始音频。这一步的意义不只是压缩——它把音频变成了
「可以用交叉熵预测的离散序列」，使音乐生成可以直接借用语言模型的全部工具。

\subsection{自回归音乐生成：从 AudioLM 到 MusicGen}\label{sec:rw-gen}

AudioLM\cite{borsos2023audiolm} 直接利用这一点：把音频分成语义 Token 与声学 Token 两级，
用 Transformer 做自回归续写，得到长时间尺度的连贯音频；MusicLM\cite{agostinelli2023musiclm}
把文本条件加入同一框架。MusicGen\cite{copet2023musicgen} 做了简化：单阶段 Transformer 直接
建模 EnCodec 的多个码本，用\textbf{delay pattern} 把并行的码本流错开一帧、拼成一条序列，
从而用一个因果语言模型同时处理多个码本；其 small 版本约 300\,M 参数，是本项目在 8\,GB 显存上
唯一可行的选择。本文沿用这套 Token 格式，但先做了一件文献里不会写的事：实测本环境的 EnCodec
与 MusicGen 权重是否真的互操作（能解码回放才算兼容），而不是假设「同系列即可互换」
（见第~\ref{sec:encodec} 节）。

\subsection{参数高效适配：LoRA}\label{sec:rw-lora}

把 300\,M 的生成模型全量微调到个人设备上并不划算，因此参数高效适配（PEFT）成为主流选择：
adapter 在层间插入小模块\cite{houlsby2019adapters}，prefix tuning 在输入端学习虚拟 Token，
LoRA\cite{hu2021lora} 则冻结原始权重、只训练低秩旁路（$W+\frac{\alpha}{r}BA$），把可训练参数
压到原来的千分之一量级。这类方法的共同前提是「基座已经会做这件事，只需要引导」。
需要强调的是，LoRA 只降低\textbf{优化成本}，并不保证目标对齐正确——本文的生成式任务正是在
这一点上踩过一个不报错的坑（见第~\ref{sec:lora} 节）。

\subsection{数据集、划分与评测口径}\label{sec:rw-eval}

GTZAN\cite{tzanetakis2002gtzan} 是最常用的基准，但 Sturm 指出其存在重复音频、标签错误、
失真与艺术家泄漏等问题，容易高估模型能力\cite{sturm2013gtzan}。FMA\cite{defferrard2017fma}
提供了规模更大、授权更清晰的替代数据；MSD\cite{bertin2011msd} 则侧重百万级曲目与元数据。
本文选择 GTZAN 作为快速验证集、FMA-small 作为主实验集，并对两者都做泄漏检查。
两个任务的全部实验共用这同一份划分（对照见第~\ref{sec:twotask} 节）。

评测口径上，两个任务的可度量性并不对等。判别式任务有唯一真值，Accuracy 与 Macro-F1 几乎
完备地刻画了「答对多少」；生成式任务没有唯一正确答案，任何指标都只覆盖质量的一个侧面。
Fréchet Audio Distance\cite{kilgour2019fad} 等参考无关指标用预训练嵌入的分布距离度量
「像不像真实音乐」，但它与人类主观判断的相关性并不稳定；与真实后续的频谱距离
（本文采用的 Log-Mel RMSE）则只衡量「接近这段真实音频」，不衡量音乐性。
本文因此把 Token 级指标、音频级距离与定性试听分开报告，不把任何一个单独当成「生成质量」。
两类指标\textbf{不可跨任务比较}，这一点在第~\ref{sec:twometric} 节还会回到。

\subsection{鲁棒性与可复现性}\label{sec:rw-robust}

真实部署中的音频会经历音量变化、噪声、压缩与片段截断，而流派分类的输入表示对这几类扰动
并不等价：以片段最大值为参考的归一化天然免疫整体增益，却对加性噪声毫无抵抗力（第~\ref{sec:robust}
节实测）。本文用七种扰动系统评测参与主实验的六个模型中的五个（冻结 AST 因权重与显存限制未纳入，
见第~\ref{sec:robust} 节）。可复现性方面，本文把它当作一等公民：固定种子、确定性 kernel、
自动化协议测试与独立审计，两个任务共用同一条纪律，但生成侧的边界更窄——采样方差尚未估计，
详见第~\ref{sec:limits} 节。

\section{数据与实验协议}\label{sec:data}

本章给出两个任务共用的数据与协议。两个任务使用同一份 FMA-small 与同一份按艺术家分离的划分，
但前端不同：判别式任务把音频变成特征与频谱，生成式任务把它变成离散 Token。因此本章的结构是
先并列、再收拢：两个数据集（第~\ref{sec:gtzan}、\ref{sec:fma} 节）之后是两条前端
（第~\ref{sec:frontend} 节），然后是划分与泄漏诊断（第~\ref{sec:leakage} 节）、两个任务共用的
防泄漏与复现纪律（第~\ref{sec:guard} 节）、协议对照（第~\ref{sec:twotask} 节），最后是共用的
软硬件环境（第~\ref{sec:env} 节）。凡是只对一个任务成立的约定，正文会标明它属于哪一侧。

\subsection{GTZAN：判别式任务的 MVP 数据集}\label{sec:gtzan}
GTZAN 包含 10 个流派各 100 首、每首约 30 秒、22\,050\,Hz 单声道音频。审计发现 1 首无法解码（\texttt{jazz.00054}），28 首与其他曲目 MD5 完全相同。我们剔除损坏文件，并对重复组只保留第一首，最终得到 \textbf{985 首}。按曲目分层划分 70/15/15（689/149/147），随机种子 42。逐流派统计见表~\ref{tab:gtzan-data}。

\input{tables/gtzan_data.tex}

GTZAN 的优点是规模小、类别均衡、加载快；缺点是标签噪声与重复音频，且缺少可靠的艺术家元数据（原始文件仅以文件名区分曲目）。因此它适合做快速迭代与教学演示，不适合作为唯一证据。生成式任务不使用 GTZAN：其每首仅 30 秒、采样率 22.05\,kHz，无法支撑 6 秒窗口与 32\,kHz 前端，第二部分全部实验都在 FMA-small 上进行。

\subsection{FMA-small：两个任务共用的主数据}\label{sec:fma}
FMA-small 包含 8\,000 首、8 个均衡流派的 30 秒片段，名义采样率 44.1\,kHz（实测 44.1/48/22.05\,kHz 三档混合，见附录表~\ref{tab:data}）。初步按曲目分层 70/15/15 划分后，泄漏检查发现测试集中 \FmaTrackLeak{} / \FmaTrackLeakN{} 首（\FmaTrackLeakPct\%）与训练集共享艺术家。因此主实验改用\textbf{按艺术家分离}的划分（每位艺术家整体进入且仅进入一个集合，测试集与训练集的艺术家重叠为 0），并按流派保持大致比例（由于艺术家作品数不均，逐类比例并不完全相等，见附录表~\ref{tab:data}）。曲目级划分保留为泄漏对照实验，泄漏的机制与量化对比见第~\ref{sec:leakage} 节。数据审计还发现 6 首损坏音频（与官方 SHA1 清单一致，属上游数据问题）与 4 首中心 5 秒数字静音的曲目；前者剔除，后者保留并在附录中说明。艺术家分离划分的逐流派数量见表~\ref{tab:fmasplit}。

\input{tables/fma_split.tex}

需要强调，艺术家分离划分不是「免费」的：由于部分艺术家拥有大量作品（最多的一个艺术家有 208 首），划分后逐流派的验证/测试比例并不完全相等（例如 Folk 的验证集 249 首、Instrumental 的验证集 82 首）。这会轻微影响早停与阈值选择，但测试集仍有 126--191 首/类，宏平均指标对类别比例不敏感。

\subsection{两条前端：频谱特征与离散 Token}\label{sec:frontend}

两个任务读同一批曲目，但喂给模型的东西不同：判别式任务需要能区分流派的时频表征，
生成式任务需要能被交叉熵预测的离散序列。两条前端只在「读同一个 30 秒片段」这一点上共享。

\paragraph{（a）判别式前端：特征与频谱}
判别式任务的全部模型使用\textbf{每首曲目中心 5 秒}片段，重采样到 22\,050\,Hz 单声道。
传统模型输入 209 维人工特征，深度模型输入 $64\times216$ 的 Log-Mel 频谱（三条支路见图~\ref{fig:pipeline}）：
\begin{equation}
  S_{\mathrm{dB}}(m,t)=10\log_{10}\!\left(\sum_{f} |X(f,t)|^{2}\,H_{m}(f)\right),\qquad
  \tilde{S}=S_{\mathrm{dB}}-\max_{m,t} S_{\mathrm{dB}},
\end{equation}
其中 $H_m$ 为 64 个 Mel 滤波器，$|X(f,t)|^2$ 为短时傅里叶功率谱（$n_{\text{fft}}=1024$，hop$=512$）。以片段最大值为参考的归一化使表示对整体增益不敏感，这一点在鲁棒性实验中会再次出现。

\subsection{划分协议与泄漏诊断}\label{sec:leakage}

FMA-small 的元数据包含艺术家字段。我们先用常规的按曲目分层划分，然后检查测试集与训练集的艺术家重叠：\FmaTrackLeak{} / \FmaTrackLeakN{} 首（\FmaTrackLeakPct\%）测试曲目与训练集共享至少一位艺术家。同一乐队的作品在音色、录音设备与编曲习惯上高度相似，这会为模型提供一条「认乐队」而非「听懂流派」的捷径。

\subsection{防泄漏与可复现约束}\label{sec:guard}
两个任务共用同一条纪律，但落点不同，下面每条都写明两侧各自的做法。

\begin{itemize}
  \item \textbf{先按曲目划分，再切片}：判别式的 5 秒片段与生成式的 6 秒窗口都在曲目内部切，
  同一曲目绝不跨集合；
  \item \textbf{统计量只在训练集上拟合}：判别式的 StandardScaler 与 Log-Mel 归一化、
  生成式的码本频率先验与词表统计，都只统计训练集；
  \item \textbf{选型只看验证集}：判别式按验证集 Macro-F1 早停，生成式按验证集 NLL 早停，
  测试集在模型冻结后只评估一次；
  \item \textbf{预训练权重冻结}：判别式的 AST 主干与生成式的 EnCodec、MusicGen 基座都不训练，
  只训练线性头、预测模型或 LoRA 旁路；
  \item \textbf{固定种子并开启 cuDNN 确定性}：判别式为 42/123/2024 三种子；生成式的 Token
  预测模型同样三种子，但采样式生成（MusicGen 续写、LoRA 适配）只有单一种子，温度与 top-$k$
  固定，其方差未估计，这一点在第~\ref{sec:limits} 节作为局限列出；
  \item \textbf{自动化校验}：判别式协议由 \texttt{tests/test\_protocol.py} 校验划分不重叠、
  特征对齐、标准化器只看训练集与 checkpoint 可推理，并由独立审计复核；生成式协议尚无同等
  覆盖，只做了窗口归属与 Token 行数的逐条核对。
\end{itemize}

\subsection{模型族}

六个模型分三组：浅层基线（SVM、MLP）、自建深度模型（CNN、CRNN、轻量 Transformer）与
预训练迁移（冻结 AST）。三组共用同一份 209 维特征或同一批 5 秒片段，差异只在网络结构与输入表示。

\paragraph{传统基线：SVM 与 MLP}
SVM 使用 RBF 核（$C=10$，$\gamma=$scale），MLP 为两层全连接（256-128，ReLU，Adam，early stopping），两者均由 scikit-learn\cite{pedregosa2011sklearn} 实现。二者共享同一份 209 维特征，标准化器仅在训练集拟合。

\paragraph{CNN}
输入 $1\times64\times216$ 的 Log-Mel，4 个卷积块、每块两个 $3\times3$ 卷积加 BatchNorm、ReLU 与
$2\times2$ 最大池化，随后自适应平均池化到 $2\times4$ 并接线性分类头。设计上的关键取舍是末尾
自适应池化：它让同一套权重能吃 GTZAN 与 FMA 的等长片段，而不必为每个数据集改结构。

\paragraph{CRNN}
CNN 前端（3 个卷积块，池化 $(2,2)/(2,2)/(2,1)$）先把频率维压到 1，再把时间维展开为序列送入
双向 GRU（隐藏维 96），对时间维取平均后分类。与 CNN 相比，它把「频谱图」当作「时间序列」，
理论上更适合建模音乐的时间演化；实测收益见第~\ref{sec:results} 节。

\paragraph{轻量 Transformer}
把每一帧的 64 维 Mel 向量线性投影到 $d=128$，加可学习位置编码，经 2 层 Pre-LN Transformer
（4 头，FFN 256），对时间维平均池化后分类。规模刻意压到 30 万参数，以匹配 8\,GB 显存与课程
算力预算——这也让它成为「在万首以下数据上从头训练自注意力」的对照组。

\paragraph{AST 迁移学习}
使用 \texttt{MIT/ast-finetuned-audioset-10-10-0.4593}（86M 参数，AudioSet 预训练）。音频重采样到
16\,kHz、取中心 5 秒并补零到 10.24 秒，经 AST 特征提取器得到 $128\times1024$ 频谱；冻结主干，
取 \texttt{pooler\_output} 的 768 维表示，在训练集上训练 StandardScaler + 逻辑回归分类头
（$C$ 由验证集选择）。该组单独标记为「迁移学习组」，也是唯一使用 16\,kHz 而非 22.05\,kHz 的支路。

三个自建深度模型的层结构、参数量与训练预算见表~\ref{tab:arch}；正文只留在设计上需要解释的
取舍，逐层清单不再复述。

\subsection{训练流程与正则化}

所有深度模型共享同一套训练流程：AdamW\cite{loshchilov2019adamw} 优化、余弦退火、batch size 32、
最多 30 个 epoch，按验证集 Macro-F1 早停（patience 8）并保存最佳权重，测试集只在训练结束后
评估一次。该流程被封装在 \texttt{src/train\_cnn.py} 中，模型之间的差异仅在网络结构与输入表示，
算法~\ref{alg:train} 给出完整循环。

\begin{algorithm}[H]
\caption{统一训练与评估流程}\label{alg:train}
\KwIn{训练/验证/测试划分 $D_{tr},D_{va},D_{te}$；模型 $f_\theta$；最大轮数 $E$；耐心 $p$}
\KwOut{最佳权重 $\theta^\star$；测试指标}
在 $D_{tr}$ 上拟合标准化器 / 归一化统计量\;
\For{$e=1$ \KwTo $E$}{
  打乱 $D_{tr}$，按 batch 采样\;
  可选：对 Log-Mel 施加 SpecAugment\;
  前向计算、交叉熵（可选标签平滑）、反向传播、AdamW 更新\;
  在 $D_{va}$ 上计算 Macro-F1 $F_e$\;
  \eIf{$F_e > F_{\text{best}}$}{
    $\theta^\star \leftarrow \theta$；$F_{\text{best}} \leftarrow F_e$；耐心计数清零\;
  }{
    耐心计数加 1\;
  }
  \If{耐心计数 $\ge p$}{break\;}
}
加载 $\theta^\star$，在 $D_{te}$ 上评估一次并冻结结果\;
\end{algorithm}

针对小数据过拟合，训练时另加两类正则化，二者的效果在验证集上做消融：
\begin{itemize}
  \item \textbf{SpecAugment}\cite{park2019specaugment}：对归一化后的频谱随机遮挡 2 个频带（宽度 $\le 8$）与 2 个时间段（宽度 $\le 16$），遮挡值置为 0（训练集均值）；
  \item \textbf{标签平滑}\cite{szegedy2016labelsmoothing}：把独热目标改为
  \begin{equation}
    q_k=(1-\epsilon)\,y_k+\frac{\epsilon}{K},
  \end{equation}
  其中 $K$ 为类别数，$\epsilon=0.05$；同时把 dropout 从 0.3 提高到 0.4。
\end{itemize}
所有消融只使用验证集选型，测试集不参与任何决策；结果见第~\ref{sec:results} 节。

\subsection{实现与资源占用}

推理延迟、模型体积与训练成本的横向对比放在结果章（第~\ref{sec:cost} 节），与部署取舍一起讨论；
本节只交代影响可复现性的实现细节。

所有音频特征与 Log-Mel 在每个数据集上只计算一次并缓存为 \texttt{.npz}，训练时直接读取，避免重复解码 MP3；DataLoader 使用 \texttt{num\_workers=0} 并配合页锁定内存，保证可复现优先于吞吐；深度模型开启 cuDNN 确定性（见第~\ref{sec:guard} 节）。在 8\,GB 显存下，batch size 32 足以训练全部自建模型，峰值显存远低于上限。


\subsection{评估指标}

对测试集 $D_{te}=\{(x_i,y_i)\}_{i=1}^{N}$，模型预测 $\hat y_i$。Accuracy 与 Macro-F1 定义为
\begin{align}
  \mathrm{Acc} &= \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}[\hat y_i=y_i],\\
  \mathrm{Macro\text{-}F1} &= \frac{1}{K}\sum_{k=1}^{K}
  \frac{2P_kR_k}{P_k+R_k},
\end{align}
其中 $P_k,R_k$ 分别是第 $k$ 类的精确率与召回率。Macro-F1 对每个类别等权，能暴露「只擅长少数流派」的问题；逐类 F1 与混淆矩阵用于错误分析。除分类指标外，我们记录训练时间、单片段推理延迟（batch 1，中位数）、参数量与模型文件大小。

\subsection{重复实验与统计}

深度模型使用 3 个随机种子（42/123/2024）重复训练，报告均值与标准差；SVM 的硬预测与种子无关，因此三个种子的指标相同（种子只影响 Platt 概率校准）。AST 为单种子迁移实验。对于 $n=147$（GTZAN）与 $n=1{,}199$（FMA-small）的测试集，比例指标在 $p=0.5$ 附近的 95\% 置信半径约为 $\pm 7.2$ 与 $\pm 2.8$ 个百分点；因此 1--2 个百分点的差异不应被过度解读。

\subsection{错误分析：类别、置信度与时间稳定性}\label{sec:error}

\subsection{小结}\label{sec:p1summary}

判别式任务的结果可以收成四条。其一，\textbf{预训练是单点收益最大的因素}：冻结 AST 在两个数据集上
都取得最佳 Macro-F1（0.814 / 0.590），代价是 145 倍体积与约三个数量级的延迟。其二，
\textbf{自建模型的排序随数据规模翻转}：GTZAN 上 CNN 领先 CRNN 约 3 个百分点，FMA 上 CRNN 反而
领先 2.2 个百分点——数据足够时，建模时间演化的结构才开始起作用。其三，\textbf{正则化与训练预算
都不是有效旋钮}：SpecAugment 与标签平滑的增益落在种子波动内，加长到 60 轮在两个数据集上互有
胜负。其四，\textbf{模型会自信地犯错，也怕脏输入}：Transformer 的 64 个错误里有 16 个置信度
超过 0.9，而 10\,dB 噪声下平均掉约 42 个百分点，此时传统模型反而更稳。这四条在第~\ref{sec:discussion}
节与生成式任务的结论合并讨论。

\section{讨论}\label{sec:discussion}

本章分三层：第~\ref{sec:negresult} 节之前的几节汇总两个任务的主要发现并比较它们的可度量性；
随后按任务解释机制——判别式侧解释预训练收益与自建 Transformer 为何失利，生成式侧解释误差
累积与指标背离；最后是效度威胁、伦理与可复现性。凡是只涉及一个任务的段落，标题会标明。

\subsection{主要发现}

两个任务的结论放在一起看，可以压缩成八条。

\begin{enumerate}
  \item \textbf{预训练是单点收益最大的因素}。冻结 AST 主干 + 线性头在判别式任务的两个
  数据集上都取得最佳 Macro-F1（GTZAN 0.814、FMA 0.590），分别比最好的自建模型高 6.1 与
  9.8 个百分点。但这份收益属于「预训练数据 + 架构」的组合，不能简单归因于 Transformer
  本身——从头训练的轻量 Transformer 反而最弱。
  \item \textbf{深度模型不是免费的午餐}。在 GTZAN 上，CNN 比 SVM 高约 4.7 个百分点，
  训练成本却高约 250 倍；在 FMA 上，CNN 甚至落后于 CRNN。数据规模、标签质量与正则化共同
  决定排序，架构只是其中一环。
  \item \textbf{数据泄漏能把结论整个翻转}。同一批特征、同一模型，仅把划分从艺术家分离换成
  按曲目，CNN 的 Macro-F1 就从 0.470 变成 0.568。泄漏不是「多几个点」的小问题，而是会让
  模型选择与论文结论失效。
  \item \textbf{干净输入上的冠军在扰动下可能垫底}。CNN 在 GTZAN 上排名第一，但在 0\,dB 噪声
  下是五个模型中最差的（0.122）；除增益外，每个扰动条件的绝对第一都是 SVM。
  \item \textbf{离散 Token 层面确实可学，但学到的很少}。在生成式任务中，小 Transformer 的
  free-running Top-1 为 \TokTransformerFree{}、NLL 为 \TokTransformerNll{}，明显优于
  Bigram 基线（\TokBigramFree{}）与均匀分布（$\ln 2048=7.62$）；但绝对水平只有随机猜
  （0.049\%）的四十几倍，远不足以生成有结构的乐句。
  \item \textbf{误差累积是这两种能力之间的墙}。Teacher-forced 口径下模型能拿到 3.36\%，
  一旦改为吃自己的预测就掉到 2.19\%；解码回音频后，它与真实未来"像"但不同。判别式任务
  的高准确率不能外推为"理解了音乐的时间结构"，这是两个任务之间最需要说清的界限。
  \item \textbf{目标对齐错误会把实现缺陷伪装成容量不足}。LoRA 初版的目标值一直停在均匀分布
  之上，当时被解释为"适配容量不够"。实际原因是标签维度写错，梯度方向本身无意义
  （错误布局 11.08 / 正确布局 5.46 / 均匀分布 7.62）。修正后同一条配置立刻有效。
  \item \textbf{训练目标值下降不等于生成质量提升}。修正后我们又试了三个旋钮——训练步数
  （1200→3600）、目标窗口（掩前缀→全窗口）、适配秩（$r{=}8\!\to\!16$）。三者都能把
  NLL 压得更低，但没有一个能显著改善音频（配对检验 $|t|<1.1$）。若只看训练曲线，会得到
  三个"改进"；逐曲检验后，它们都不是。
\end{enumerate}

\subsection{判别式与生成式：同一种纪律，两种可度量性}\label{sec:twometric}

两个任务共用同一份划分、同一套"测试集只评一次"的纪律，但它们能被度量的程度差别很大，
这一点直接决定了报告应该怎么写。

判别式任务的评价几乎是完备的：给定片段，标签唯一，Accuracy 与 Macro-F1 有明确含义，
混淆矩阵还能指出错在哪。生成式任务则只有\textbf{半个}评价：我们可以精确度量"模型给真实
未来的概率有多大"（NLL、Top-1），这是一件干净的事；但"这段续写好不好"没有唯一答案，
用与真实后续的 Log-Mel 距离只能说明"接近这段录音"，不能说明音乐性。

因此本文对生成式任务采取三重分开报告：Token 级指标（可精确度量）、音频级距离（可与基线
对比，但不等于质量）、定性试听（只能说明个别样本的听感）。任何一处都不把三者混为"生成
质量提高了"。第三节的协议表已经把两种任务的指标并列列出，刻意不做跨任务数值比较。

反过来说，正因为生成式任务的目标更模糊，它\textbf{对实验卫生的要求反而更高}：一旦目标对齐
有偏差，loss 仍然会"看起来在下降"，报告者很难从曲线上察觉。本文的 LoRA 事故就是这个
现象的直接证据。

\subsection{负结果是怎么被辨别出来的}\label{sec:negresult}

本文有三个结论曾被自己的数据推翻，每一次都靠一个具体的检验，而不是靠直觉。把这些
检验写出来，比结论本身更有教学价值：

\begin{enumerate}
  \item \textbf{去掉最优样本后复算}。初版 LoRA 的音频距离均值改善 0.80\,dB，看上去成功；
        但去掉改善最大的那一首后只剩 0.16\,dB。修正后的版本在同样处理后仍有 0.99\,dB，
        7/8 首变好。\emph{只有第二个版本值得写进结论。}
  \item \textbf{逐曲配对检验而不是只看均值}。8 首样本上，v3（3600 步）比 v2（1200 步）
        均值低 0.20\,dB，像是"多训有用"；配对后 $t=-0.47$，与噪声无法区分。秩提升到 16
        虽然 NLL 更低，音频却更差 0.68\,dB 且相对基线不显著。
  \item \textbf{按下降速度判断是否欠训练，而不是看最优轮次}。Token 模型的最优轮次落在
        41--45，看起来"还在改善"；但把验证 NLL 按 5 轮一段统计，下降量呈几何衰减
        （$0.130\to0.099\to0.060\to0.030\to0.015\to0.0078\to0.0048\to0.0021$），
        外推的剩余可降幅度已小于末 5 轮的抖动。平台期的抖动随机把最优轮次挑到了最后一轮。
\end{enumerate}

第三条尤其值得强调：它推翻的正是\emph{本文自己在上一轮加长训练后的判断}。当时仅凭
"最优轮次撞上限"就写下"仍未训够"，一天后按下降速度复核便发现是误判。负结果的可靠性
不取决于它是否符合预期，而取决于有没有做能否证伪它的检验。

\subsection{误差累积：3.36\% 为什么会掉到 2.19\%}\label{sec:errcum}

Token 预测的两个口径差距达 35\%（teacher-forced 3.36\% $\to$ free-running 2.19\%，
第~\ref{sec:p2results} 节），这是生成式任务最需要解释的一个数字。

机制是标准的自回归误差累积：teacher-forced 口径每一步都喂真实历史，模型的错误互相独立；
free-running 口径把自己的预测喂回去，第 $t$ 步的错误进入第 $t+1$ 步的输入分布，于是
错误不再是噪声而是偏差。两个结构的差异恰好印证这一点：小 Transformer 的 teacher-forced
Top-1 更高（天花板更高），但 free-running 相对损失约 35\%，比 LSTM 的约 25\% 更严重——
注意力模型对输入分布偏移更敏感；而循环结构在回灌下退化更慢，代价是上限更低。

需要强调的是，这个数值\textbf{不能}直接外推到更长的 horizon。本文只做了 1 秒（50 帧）的
预测，误差在这 50 步内的累积已经吃掉三分之一；若 horizon 拉长到整句或整曲，
没有显式的结构约束（分段、重采样、planning）时误差会指数级放大。这正是
AudioLM 一类工作引入两级 Token 与多尺度生成的原因\cite{borsos2023audiolm}：
单层自回归在小 horizon 上可用，在长 horizon 上必须靠结构。

\subsection{Token 指标与音频距离为何背离}\label{sec:disagree}

第~\ref{sec:p2loraabl} 节的三个旋钮给出了一个反直觉的结果：训练步数从 1200 加到 3600，
NLL 从 6.06 降到 5.73（相对 5.5\%），音频距离却只从 17.91 微降到 17.71，配对检验不显著
（$t=\GenVThreeVsFtT$）；适配秩提到 16 时 NLL 更低（5.68）而音频反而回升到 18.59
（相对基线 $t=\GenRSixteenVsBaseT$）。若把 NLL 当作质量代理，这里会得到两个错误结论。

背离有两个来源。其一是\textbf{平均 vs 关键帧}：交叉熵对整段概率质量的平均敏感，而听觉
质量由少数关键帧决定——起音、瞬态、鼓点的位置。模型可以把绝大多数"平稳帧"的概率再压低
一点，从而降低平均 NLL，却对决定听感的瞬态帧仍然没把握；这类改进在频谱距离上几乎不可见。
其二是\textbf{分布覆盖 vs 单点命中}：NLL 奖励把概率集中到训练集常见模式上，而这恰是
"更安全、更像平均值"的方向；LoRA 修正后模型变"保守"了，距离下降主要来自不再产生明显
错误的帧，而不是产生了更好的音乐。

因此本文的结论只到这一层：\textbf{修正目标对齐带来了可测的音频改善且不依赖单一样本}；
至于"哪个配置音乐上更好"，Token 级指标无法回答，需要规模化的主观评分——本文没有做，
这是第~\ref{sec:limits} 节列出的局限之一。

\subsection{预训练、架构与成本}
AST 在两个数据集上都是最强的单模型，但其优势来自 AudioSet 预训练而非 Transformer 架构本身：
同等轻量、从头训练的 Transformer 在 GTZAN 上只有 0.541 的 Macro-F1，且训练损失迅速降到接近 0、
验证损失抬头——典型的小样本过拟合。卷积与循环结构带有局部性、平移等变性等先验，而自注意力
需要从数据中自行学习这些关系；在千首规模上，「缺少归纳偏置」的代价大于建模长程依赖的收益。

同为 Transformer 架构的 AST 预训练后反而最强，说明问题不在架构本身，而在\textbf{训练数据与
正则化}；第~\ref{sec:results} 节的 SpecAugment / 标签平滑消融正是对这一判断的直接检验，
结果是否定的——正则化没能补上数据。代价方面，AST 的权重体积是 CNN 的约 145 倍、单片段延迟
约 270--300 倍（第~\ref{sec:cost} 节），是否值得取决于场景：离线批量标注可以接受，
实时交互则应优先考虑 CNN 或蒸馏后的小模型。

\subsection{鲁棒性的进一步解读}

第~\ref{sec:robust} 节已经报过现象（增益免疫、噪声最致命、SVM 在脏输入上领先），
这里只解释机制——按「表示」而不是「模型」来读表~\ref{tab:robust}：
\begin{itemize}
  \item 增益免疫与增益敏感的分界就在表示上：深度模型吃的是片段内最大值归一的 Log-Mel，
  对纯增益严格不变；传统模型的 MFCC 是绝对 dB、还含 RMS，增益变化直接移动特征分布。
  \item 噪声抬高了频谱的动态范围地板。以 \texttt{blues.00008} 为例，干净片段的 Log-Mel
  最小值是 $-80$\,dB，10\,dB SNR 时变为 $-46.3$\,dB；在 \texttt{ref=max} 归一化后，
  安静帧整体上移几十 dB，相当于强烈的分布外输入。这解释了为什么连「几乎听不见」的
  30\,dB 噪声也能让 CNN 大幅掉点。
  \item 片段长度同时改变上下文与时间尺度：3\,s 片段被线性拉伸到 216 帧（1.66 倍），
  10\,s 被压缩到 216 帧（2 倍）。CRNN 的 GRU 对时间尺度最敏感，3\,s 时 Macro-F1 只剩
  0.169；而 SVM/MLP 的统计量在更长窗口上反而更稳（10\,s 提升约 5 个百分点）。
\end{itemize}

\subsection{威胁与局限}\label{sec:limits}

按效度维度组织，每个维度给出两个任务各自的威胁。

\paragraph{构念效度}
判别式侧：流派标签是人为构造的，同一首歌可能同时属于多个流派；模型学到的是「数据集标注者
的偏好」，而不是音乐的本质，GTZAN 的标签噪声与 FMA 的宽类别都放大了这一问题。
生成式侧更根本："续写得好不好"没有唯一真值，本文用的 Log-Mel RMSE 只奖励"贴近这一首原曲"，
对自由创作式的续写天然不利，与"音乐性好"是两件事。

\paragraph{内部效度}
判别式侧：尽管固定了划分、种子与预处理，GPU 的非确定性仍可能带来 1--2 个百分点的波动
（例如自适应平均池化的 CUDA 反向传播没有确定性实现\footnote{具体为
\texttt{adaptive\_avg\_pool2d\_backward\_cuda}。}），因此只对大于 3 个百分点的差异做解释。
生成式侧：除 Token 预测模型跑了 3 个种子外，MusicGen 的前缀续写与 LoRA 适配都是单一随机
种子，生成采样的方差未被估计；更值得警惕的是，LoRA 初版的目标对齐错误曾稳定伪装成
"容量不足"——内部效度的威胁在生成式任务上更隐蔽，因为它不报错。

\paragraph{外部效度}
判别式侧：两个数据集都以西方流行音乐为主，未覆盖中文流行与民族音乐；片段统一取中心 5 秒，
未利用整首 30 秒的结构；扰动实验只覆盖增益、噪声与片段长度，未覆盖变速、混响与现场录音。
生成式侧：文本条件只覆盖 8 个流派的模板句，主表续写统一取 3 秒的稳定口径（实测可到 12 秒，
16 秒以上触发位置嵌入断言），评估只有 8 首测试曲，
因此不能说明模型在更长 horizon 或任意文本条件下的表现。

\paragraph{统计效度}
判别式侧：GTZAN 测试集仅 147 首，比例指标的 95\% 置信半径约 $\pm 7$ 个百分点；FMA 为
1,199 首，约 $\pm 2.8$ 个百分点；3 个种子只能给出粗略的方差估计。
生成式侧：8 首样本上配对检验的统计功效很低，本文因此把所有 0.3\,dB 量级的差异一律判为
不显著——这是保守的选择，代价是可能漏掉真实的小效应。

\paragraph{实现层面}
AST 的 16\,kHz 与 FMA 原始 44.1/48\,kHz 存在域差异，5 秒补零到 10.24 秒意味着一半输入是
静音；受算力限制，AST 只做线性探针、未微调，其结果代表「冻结表征的线性可分性」而非 AST 的
上限。生成式侧：官方 \texttt{audiocraft} 实现对本环境 PyTorch 版本有强约束，本文改用
\texttt{transformers} 的解码器直连，其位置索引上限把续写截在 3 秒——这一点已如实写进结果，
未用"跑通 3 秒"冒充"完成 5 秒续写"；更长的长度见第~\ref{sec:musicgen} 节表~\ref{tab:horizon} 的实测。

五条叠在一起意味着：本文能够可靠地说"修正目标对齐带来了可测的改善"，但\textbf{不足以}
支撑任何关于音乐质量的更强主张。

\subsection{伦理与数据授权}

GTZAN 与 FMA 的音频版权归各权利人所有，本文只使用其进行研究与课程演示，不再分发音频；
仓库不包含原始音频与模型权重，只提交划分清单、代码与结果。模型可能强化「流派」这一西方
音乐产业分类体系，在跨文化应用中需要重新审视标签体系与标注者构成。

生成式部分多一层问题。本文使用的 EnCodec 与 MusicGen 权重各有其许可条款（研究用途），
仓库不重新分发这 5.8\,GB 权重，只给出下载与复现脚本；生成的续写音频同样不随仓库发布，
仓库内只保留测量结果与少量可核查的样例。此外，续写模型有可能在局部复现训练曲目的片段——
这也是本文不发布生成音频的原因之一。凡引用本项目的生成结果，应同时引用其基座模型及其许可。

\subsection{可复现性总结}

判别式侧的复现纪律与校验机制见第~\ref{sec:guard} 节，此处只补两点差异。其一，GPU 非确定性
带来的细微数值差异不完全可复现，这是两个任务共有的边界。其二，生成式侧的边界更窄：
采样式生成只有单一种子，其方差未被估计；EnCodec 与 MusicGen 权重不在仓库内，需按附录
第~\ref{sec:appendix-gen} 节的参数重新下载并适配。可以完全复现的是判别式的全部数字，
以及生成式的 Token 级指标与音频距离测量本身。

\subsection{对课程项目的启示}
\begin{enumerate}
  \item \textbf{协议比模型数量更重要}：同一划分、同一批片段、训练集拟合预处理，才能让「谁更强」这句话有意义；
  \item \textbf{先排查泄漏再谈提升}：FMA 的曲目级划分让 81\% 的测试曲目与训练集共享艺术家，若不检查，任何「提升」都可能只是记住了乐队；
  \item \textbf{鲁棒性与部署成本是模型选择的一部分}：干净输入上的冠军在噪声下可能垫底，346\,MB 的预训练模型也不适合实时场景；
  \item \textbf{可视化与失败案例比单一准确率更有解释力}：混淆矩阵、置信度、时间轴让观众直观看到模型「什么时候会翻车」；
  \item \textbf{先验证目标对齐，再谈容量}：在未训练的模型上比较两种标签布局（11.08 / 5.46 / 均匀分布 7.62），
  五分钟就能判定梯度方向是否有意义。对齐错了，加容量、加步数、加秩都不会收敛；
  \item \textbf{指标必须分层报告}：训练 NLL 从 6.06 降到 5.73 的「改进」，在音频上只值 0.2\,dB 且不显著。
  凡是声称「生成质量提升」的报告，都应当交代这一层转换是否被检验过。
\end{enumerate}

\section{结论与展望}\label{sec:conclusion}

本文在一个统一、可复现的协议下做了两件事。判别式侧，比较了从 SVM 到预训练 AST 的六类流派
分类模型，并在 GTZAN（985 首）与 FMA-small（7,994 首）上检验结论的稳定性；生成式侧，
把预测目标换成离散 Token 序列，用同一份按艺术家分离的划分做 Token 预测、解码验证与
MusicGen 前缀续写。两个任务共用同一条纪律，但可度量性不同，因此所有数字分开报告，
从不跨任务比较。

\textbf{判别式侧的核心发现四条}：预训练表示带来最大的单点收益（GTZAN 0.814、FMA 0.590，
分别比最好的自建模型高 6.1 与 9.8 个百分点）；深度模型在干净输入上领先，但在噪声与短片段下
并不比传统方法稳健（0\,dB 噪声时 CNN 从第一变成最差）；千首规模上从头训练的轻量
Transformer 会过拟合（0.541）；艺术家泄漏足以让结论虚高约 9.9 个百分点。

\textbf{生成式侧的核心发现三条}：Token 级预测可复现、可比较，但绝对水平很低——Transformer
的 free-running Top-1 为 \TokTransformerFree{}，约为随机猜的 45 倍，远不足以生成结构化的
乐句；自回归误差累积是主要瓶颈，teacher-forced 一步到 free-running 就损失约 35\%；在修正
目标对齐后，$r{=}8$ 的 LoRA 适配能稳定改善客观音频距离（19.23$\to$\GenFtRmse{}，8 首中
7 首改善，配对 $t=\GenFtVsBaseT$），而训练步数、目标窗口与适配秩三个旋钮都不显著。

作为课程项目，本文的另一个目标是把「做研究」的流程完整走一遍：先审计环境与数据，再固定
协议、做消融、分析失败案例，最后把结果写成可追溯的报告并开源。我们刻意保留了全部负结果——
判别式侧的优化消融无效、轻量 Transformer 失利、噪声下全面崩塌；生成式侧初版 LoRA 因标签
维度错误而完全无效、以及"去掉最优样本后增益从 0.80 缩到 0.16"。因为诚实报告失败模式比
堆叠准确率更有教学价值，而其中第三个还推翻过本文自己上一轮的判断。

未来工作可以从四个方向展开：
\begin{enumerate}
  \item \textbf{更长的上下文}：当前只使用中心 5 秒片段，未来可利用整首 30 秒或滑动窗口聚合，
  并系统研究片段长度与性能的关系；
  \item \textbf{更强的鲁棒性训练}：在训练中加入噪声、增益、变速与混响增强，或采用固定 dB
  参考、每帧 CMVN 等对增益/噪声更稳健的归一化；
  \item \textbf{知识蒸馏与轻量化}：把 AST 的表征蒸馏到 CNN/CRNN，在保留大部分收益的同时
  把推理成本降回毫秒级；
  \item \textbf{跨文化与多模态}：引入非西方音乐、歌词与元数据，重新审视「流派」标签体系，
  并扩展到乐器识别、情绪识别等相关任务；
  \item \textbf{更长的生成 horizon}：当前 Token 预测只有 1 秒，主表续写取 3 秒的稳定口径
  （实测可到 12 秒，16 秒以上受 MusicGen 的 pad token 越界所限）；下一步可把
  预测器与生成模型级联（预测器提词、生成模型续写），并用规模化的主观评分检验"好听"。
\end{enumerate}
