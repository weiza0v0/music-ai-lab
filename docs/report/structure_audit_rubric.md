# 报告结构审查量规（内部使用）

用于对 `main.tex` / `phase2.tex` 做结构与叙述审查。量规改编自
`Imbad0202/academic-research-skills` 的 `structure_architect_agent.md`
（比例分配、章节目的、过渡逻辑、层级深度）与 `writing_quality_check.md`
（措辞、元叙述、术语一致），并按本报告「一个项目、两个并列任务」的实际情况改写。

审查只针对**结构与叙述**，不评价实验结论是否正确，不改动任何文件。

---

## A. 结构对称性

| 编号 | 规则 | 判定 |
|---|---|---|
| A1 | 服务于两个并列任务的同级小节，数量差不得超过 1 | 一方 5 节、另一方 1 节 = 违规 |
| A2 | 同一层级的对称小节，篇幅差不应超过约 2 倍 | 一节的字数/段数远超同类 = 违规 |
| A3 | 位于「总」层的章节（引言、相关工作、数据与协议、讨论、结论）必须对两个任务**同时**发声 | 只覆盖一个任务 = 违规 |

## B. 覆盖完整性

| 编号 | 规则 |
|---|---|
| B1 | 两个任务在研究背景、问题、相关工作、数据与协议、方法、结果、讨论、结论中都必须出现 |
| B2 | 每个任务至少一张流程图或架构图；表格数量不应相差悬殊 |
| B3 | 参考文献的引用在两个任务间应大致平衡，不得一个任务的文献只由综述段落承担 |

## C. 篇幅比例

| 编号 | 规则 |
|---|---|
| C1 | 最低层级标题下的内容少于约 150 字 → 应上并 |
| C2 | 单个小节独占全文 >35% → 应拆分 |
| C3 | 篇幅应反映重要性：主实验 > MVP，被复用的协议 > 一次性细节 |

## D. 叙述连贯

| 编号 | 规则 |
|---|---|
| D1 | 每章开头应有一句说明本章职责的句子；相邻章之间要有承接 |
| D2 | 禁止元叙述（「本节将讨论」「下面我们来看」），引言末尾的章节路线图除外 |
| D3 | 术语一致：判别式任务 / 生成式任务、Token（首字母大写）、FMA-small、Log-Mel、EnCodec 32 kHz 等，全篇写法统一 |
| D4 | 不使用「首先/其次/最后」之外的凑数三段式；条目数量由内容决定 |

## E. 冗余

| 编号 | 规则 |
|---|---|
| E1 | 同一事实不在两处重复陈述；若两处都需出现，一处给细节、一处只给指路 |
| E2 | 新增小节与既有小节的内容重叠不得 >30% |
| E3 | 后置的「补充说明」不得承担本该由前置章承担的组织职责（补丁式写作） |

## F. 单一职责

| 编号 | 规则 |
|---|---|
| F1 | 一个小节只承担一个论证职责；标题下并行讲两件事应拆分 |
| F2 | 图、表、脚注都应归属某一小节，不得出现「悬空图表」 |

---

## 输出要求

对每条发现给出：

- `kind`：symmetry / coverage / proportion / narrative / redundancy / responsibility / figure / terminology
- `severity`：P0（结构错误，必须改）/ P1（明显不均衡，应改）/ P2（润色）
- `location`：文件 + 行号 + 小节标题
- `evidence`：原文摘录（≤40 字）
- `problem`：一句话说清问题
- `fix`：具体的改法（拆/并/移/补/删，指明目标位置）

同一问题不要在相邻小节重复报三次；合并成一条。
