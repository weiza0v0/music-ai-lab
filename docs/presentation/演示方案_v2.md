## 1 先说一句：这一版的口吻是什么

不是主持人，是**一个刚做完项目、有点想吐槽、但还想把事讲清楚的人**。

三个具体特征：

1. **允许跑题一小下，然后自己拐回来。** 比如讲到数据集标注，可以吐一句"这八个类里有个叫 Pop，什么都能往里装"，然后拉回正题。
2. **允许承认无聊。** "这一页数字比较干，我尽量快，但有一个我必须说。"
3. **不逼人回应。** 全程没有"你们说对不对"、"举手我看一下"。想听的听，刷手机的刷手机，教室里这两种人都有，不冲突。

**开场第一句就定调**（这页写在 P01）：

> 今天的题目有点硬，我尽量讲得像聊天。手机该刷就刷，真听到有意思的地方，抬头看一眼我这边就行。

这句话的作用是**卸压**。观众一听就知道不用紧张，不用配合，反而更容易抬头。

### P02 · 我们想问的，其实是一个很朴素的问题

**0:56** ｜ 页型 A

**页面元素**：中间一句大字「同一批音乐，模型能听懂多少？」；下面两行小字，左边 `p(流派 | 音频)`，右边 `p(下一个 Token | 前 5 秒)`。

**讲稿**

> 问题很朴素：**同一批音乐，机器能听懂多少？**
>
> 我们拿这个问题问了它两遍。
>
> 第一遍问的是"这段音乐是什么风格"。答案是个标签，十个里面挑一个，挑完就完事。这叫分类，属于判别式任务。
>
> 第二遍问的是"这段之后会响什么"。答案不是标签，是一段声音。这叫续写，属于生成式任务。
>
> 这两件事的分数没法比。一个算"答对几成"，一个算"离真相多远"，量纲都不一样。我们从来没打算把它们放在一张榜上。
>
> 但两边用的是**同一份数据划分、同一套训练纪律、同一批测试曲目**。所以它们可以并排讲。

**技术记录**：判别式指标 Macro-F1（分类正确率按类平均）；生成式指标 Log-Mel RMSE（频谱距离，越低越近）与 Token Top-1（下一个符号猜对率）。三者不可相加、不可比较，报告 §3.6 图 5 专门讲了这件事。

### P03 · 数据从哪来：985 首，和 7,994 首

**0:50** ｜ 页型 B

**页面元素**：左右两栏对比表。

| | GTZAN | FMA-small |
|---|---|---|
| 曲目 | 985（清洗后） | 7,994 |
| 类别 | 10 | 8 |
| 测试集 | 147 | 1,199 |
| 片段 | 中心 5 秒 | 中心 5 秒 |

**讲稿**

> 数据是两套。左边 GTZAN，一千首的老数据集，十个流派，朋克、迪斯科、古典、爵士这些。清洗完之后剩 985 首。
>
> 右边 FMA-small，七千九百多首，八个类。

### P04 · 一个很容易做错的划分

**1:16** ｜ 页型 C

**页面元素**：一行两个大数字，`0.470` → `0.568`，中间一个箭头；下面一行小字「同一批特征，同一个模型，只换了划分方式」；右下角来源行。

**讲稿**

> 这一段我想讲慢一点，因为它是整个项目里**最容易做错、也最容易被忽略**的地方。
>
> 我们要把数据分成训练集和测试集。最顺手的做法是按曲目切：这首歌进训练，那首歌进测试，切完就开跑。
>
> 但音乐数据集有个特点：**同一个艺术家往往有好几首歌。** 按曲目切，很可能训练集里有这位歌手的三首，测试集里有他的另外两首。模型记住的是这个人的录音棚、他的吉他音色、他的混音习惯——它根本没在学流派。
>
> 所以我们按艺术家切：**一个人只出现在一边。**
>
> 然后我们做了个对照实验。同一批特征、同一个 CNN，只把划分从"按艺术家"换成"按曲目"——Macro-F1 从 **0.470 涨到 0.568**。
>
> 白捡 9.9 个点。因为这批测试曲里，有 81% 和训练集共享同一个艺术家。
>
> 那 9.9 个点不是模型的功劳。是数据泄漏的功劳。

**技术记录**：报告 §3.4 表 4；81.0% 的 FMAsmall 测试曲与训练集共享艺术家（按曲目划分时）。这个对照是我们自己做的，不是引用别人的结论。

### P05 · 三条比赛规则

**0:48** ｜ 页型 B

**页面元素**：三条横排，每条一行粗体 + 一行细字。

**讲稿**

> 规则三条，都很常规，但缺一条这榜就没意义。
>
> 一，每个模型跑三个随机种子，报均值。不挑最好那一次，挑最好那叫抽奖。
>
> 二，模型选型只看验证集。测试集**只评一次**，评完不许回头改。
>
> 三，就是刚才说的按艺术家划分。所有模型共用同一份划分文件。
>
> 这三条听着像废话。但你要是翻过一些课程项目的代码，会发现第一、二条是最常被违反的——尤其第二条，很多人会"顺手"在测试集上调个参数，然后分数忽然好看了。

**技术记录**：种子 42 / 123 / 2024；cuDNN 确定性开启；划分文件 `data/splits/*/splits.csv`，全模型共用。

### P06 · 六位选手的身份证

**1:01** ｜ 页型 B

**页面元素**：六行表。

| 选手 | 输入 | 参数量 | 体积 | 一句话 |
|---|---|---|---|---|
| SVM | 209 维人工特征 | — | 1.2 MB | 老派，抗造 |
| MLP | 209 维人工特征 | 8.8 万 | 1.1 MB | 比 SVM 还弱一点 |
| CNN | 64×216 log-Mel | 59 万 | 2.4 MB | 干净输入上的自建冠军 |
| CRNN | 同上 + BiGRU | 42 万 | 1.7 MB | 数据够了才反超 |
| 轻量 Transformer | 同上 + 位置编码 | 65 万 | 1.2 MB | 千首级严重过拟合 |
| AST | 128×1024 log-Mel | 8600 万（冻结） | 346 MB | 预训练，一出手就赢 |

**讲稿**

> 六位选手，可以分成三类。
>
> 前两位，SVM 和 MLP，吃的是**人工特征**——209 维，MFCC、色度、节奏直方图，全是人设计出来的。它们本身很笨，但输入里塞满了人类的经验。
>
> 中间三位是我们自己搭的：CNN 只看局部时频块；CRNN 在 CNN 后面挂了个双向 GRU，多一条"记忆"；还有一个轻量 Transformer，六十五万参数，是我们能塞进 8 GB 显存的最大号。
>
> 最后一位 AST，八千六百万参数，三百四十六兆。它不是我们训的——**AudioSet 上预训练过的权重，我们只训了它最后那层线性分类头**，七千七百个参数。
>
> 所以严格讲，它代表的是"现成表征好不好用"，不是"我们训得好不好"。这个区别在答疑的时候会被问，先记住。

**技术记录**：AST 为冻结主干 + 线性探针（best C=3，val_acc 0.859），**不是微调**，报告 §5.1；并行报告里不能说"AST 微调"。

### P08 · 冠军的代价

**0:41** ｜ 页型 C

### P10 · 模型不是白纸

**1:51** ｜ 页型 B

**页面元素**：五行表，中间一列加粗。

| 模型 | 生来就信的假设 | 数据少时 | 数据多时 |
|---|---|---|---|
| SVM / MLP | 自己没有先验，但输入的人工特征里全是 | 稳，天花板低 | 天花板低 |
| CNN | **局部性 + 平移等变** | 强 | 强 |
| CRNN | 局部性 + **循环层的记忆** | 稍弱 | 更强 |
| 轻量 Transformer | 只有位置编码，**几乎没有结构先验** | 严重过拟合 | 待观察 |
| AST | 架构同上，但**预训练把先验灌进去了** | 最强 | 最强 |

**讲稿**

> 六位选手为什么都错，但错得不一样？因为它们**生来就带着假设**。这个东西有个正式名字，叫归纳偏置——没有人教它，它自己就信。
>
> 说人话。
>
> CNN 信两件事。一是**局部性**：它只盯着眼前一小块频谱，不看全图。二是**平移不变**：同一个花纹，出现在低频还是高频、第一秒还是第三秒，它都当成同一个花纹。
> 对声音来说这个偏见特别对路。鼓点的瞬态、和弦的音程，本来就是局部的花纹。
>
> RNN 多信一条：**记忆**。它认为"我现在说什么，取决于刚才听到了什么"。这个假设也合理，音乐确实有先后。
>
> Transformer 几乎什么都不信。它只给每一帧编个位置号，然后让所有帧互相看。谁跟谁有关系，全靠数据自己学。
>
> 听起来很自由。但自由是有代价的——它没有先入为主的判断，所以**需要更多例子才能自己总结出规律**。
>
> AST 用的也是 Transformer，架构没变。变的是它在 AudioSet 上先听过两百万段音频，权重里已经装着"声音长什么样"。等于先验被提前灌进去了。
>
> 再说 SVM 和 MLP，它们俩最容易被误解。它们自己确实没有先验，但我们喂的 209 维人工特征，每一维都是人设计出来的——MFCC、色度、节奏直方图。**先验没消失，只是被提前挪到了特征里。**

**技术记录**：报告 §7.6；这一页是全场的理论核心，答辩大概率从这儿问。

### P16 · 把声音拆成符号

**0:59** ｜ 页型 C

**页面元素**：左边一条四行说明（采样率 / 码本数 / 帧率 / 每帧符号数），右边一张 RVQ 示意（自制，三层粗细递减的横条）。

**讲稿**

> 谢谢。
>
> 接着刚才那句话：分类器把音乐当照片。要让它当视频，先得解决一个技术问题——**声音怎么变成能"接着猜"的东西。**
>
> 声音是一串连续的波形，密密麻麻的数字。你没法直接"猜下一个数字"，因为下一位小数有无数种可能。
>
> 所以要先离散化。我们用的是 EnCodec：32 kHz 采样，每秒切 50 帧，每帧用 **4 个码本**各取一个符号。
>
> 一段音频，就这么变成了一串整数。你可以理解成给音乐注了一套拼音——每个音都有编号，写下来就是文本。
>
> 好处是立竿见影：**"预测音频"变成了"预测下一个符号"**，跟语言模型做的事一模一样，交叉熵直接能用。

**技术记录**：EnCodec 32 kHz、4 码本、50 Hz，每帧 4 个 Token；报告 §6.2 表。踩过的坑：EnCodec 输出第一维是分段数不是批大小，当批维用会静默丢样本。

### P24 · 最贵的一课

**1:03** ｜ 页型 B

**页面元素**：三个数字竖排 11.08 / 5.46 / 7.62，每行一句注释。

>
> 步数从 1200 加到 3600，数字从 17.91 变到 17.71，看着好一点点，但配对检验的 t 值掉到 −0.47，**不显著**，也就是跟没改一样。

### P26 · 为什么只有 3 秒

**1:02** ｜ 页型 B

**页面元素**：长度-耗时表。

| 续写长度 | 耗时（RTX 4060） | 情况 |
|---|---|---|
| 3 秒 | 5.6 秒 | 8/8 曲目稳定，主结果口径 |
| 6 秒 | 16.3 秒 | 可生成 |
| 8 秒 | 18.3 秒 | 可生成 |
| 12 秒 | 35.4 秒 | 可生成 |
| 16 / 20 秒 | — | 崩：位置嵌入索引越界 |

**讲稿**

> 每次讲完这段，一定会有人问：能不能更长？
>
> 能，但不是改个数字那么简单。
>
> 我们在其中一首上试过：3 秒出结果要 5.6 秒；6 秒要 16 秒；8 秒要 18 秒；12 秒要 35 秒。都出得来。
> 再往上，16 秒、20 秒，**直接崩。**
>
> 崩的地方挺意外的，不在长度表上，在 MusicGen 的一个特殊符号：它的编号是 2048，而词表只到 2047。序列一长就容易走到那条路，然后断言失败。
>
> 所以 3 秒是我们**八首测试曲都能稳定跑完**的口径，不是它的能力上限。真要稳定出 15 秒以上，得换官方那套生成实现，那是另一条工程路线。
>
> 我把这个说清楚，是因为写"AI 能生成 30 秒音乐"很容易，写"我们能稳定生成 3 秒"很难看——但难看的那句是真的。

**技术记录**：`demo/README.md` §3.5；峰值显存 1.35–1.51 GB；audiocraft 需 Python 3.10 + torch 2.1，与本环境冲突。

### P27 · 指标不等于好听

**0:59** ｜ 页型 C

**页面元素**：`generation_spec.png` 整张（四列频谱对照）；下方一行小字「左起：前缀 / 真实 / 原始 / 适配」。

**讲稿**

> 最后这张图，是四段音频的频谱。
>
> 从左到右：前缀、真实、原始续写、适配后续写。你能看出来，三四两列跟第二列都在同一片区域，但纹理不一样。
>
> 我们所有的"改善"，都是拿这两列跟第二列算距离算出来的。
>
> 这就带出一个不太好意思说的事实：**这套指标奖励的是"像原曲"，不是"好听"。**
> 如果模型编出一段更抓耳、但走了另一条旋律线的续写，在这个指标上它会输。
>
> 所以我们从头到尾只敢说"客观距离变近了"，不敢说"变好听了"。主观听感评分我们只做了少量试听，没有规模化的评测——这也是报告里明确写着的局限。

**技术记录**：Log-Mel RMSE 为频谱距离；主观评测未规模化（报告 §7.9 局限）；生成音频由 MusicGen-small（CC-BY-NC 4.0）产生，课堂可用、不公开发布。

### P28 · 结案

**1:13** ｜ 页型 A

**页面元素**：三行结论 + 一行五个负结果；字号逐级变小；最后一行留白。

**讲稿**

> 收个尾，三句话。
>
> 一，判别式这边，最大的单点收益来自预训练，不来自架构。0.814 对 0.753，代价是 270 倍延迟、145 倍体积。
>
> 二，模型排序会随数据规模翻转。一千首的时候 CNN 赢，八千首的时候 CRNN 反超。你对"哪个模型更强"的直觉，取决于你手上有多少数据。
>
> 三，数据泄漏能让结论虚高十个点。只换一种划分方式，0.470 就变成 0.568。
>
> 生成式这边一句话：能预测，学得很少，修好对齐后有可测的改善，但三个旋钮都没用。
>
> 最后回到开头那句话。这个报告里有五个负结果：正则化没用、轻量 Transformer 在小数据上崩、加噪声 CNN 垫底、LoRA 初版完全失效、三个旋钮调了没用。
>
> **它们一个都没删。**
>
> 我们能证明的是：这条路走得通，而且我们知道它现在走到哪。至于"做好"——还早。
>
> 谢谢大家，手机可以继续刷了。

## 10 Q&A 预案（12 问，附带温和的答法）

| 问 | 答 |
|---|---|
| 为什么不用更大的 Transformer？ | 8 GB 显存 + 一千首数据，加宽加深只会过拟合更快。我们做过 30 vs 60 轮的预算消融，加长训练也没救回来。 |
| AST 更强为什么不用它？ | 延迟 270 倍、体积 145 倍，实时场景用不了。而且它是冻结主干 + 线性头，代表的是"现成表征的线性可分性"，不是我们训出来的。 |
| 准确率这么低是不是模型不行？ | 部分原因是标签本身模糊。FMA 八个类里 Pop 这类宽标签，人工标注者之间也会分歧，Pop 的 F1 只有 0.24–0.43。 |
| 为什么只有 3 秒？ | 3 秒是八首曲目都能稳定跑完的口径，不是上限。更长的会撞上 MusicGen 的位置索引越界，24 字说清就是"它的特殊符号编号超了词表"。 |
| 能不能续写整首歌？ | 不能。报告里明确列为未做项，要做得换生成实现，是另一条工程路线。 |
| 生成的和弦对不对？ | 我们没有做和声层面的评估，只有频谱距离和少量试听。这个是真空白。 |
| 2.19% 有什么意义？ | 它的意义是"比 persistence 和 bigram 强"，说明确实学到了局部动态；绝对值说明离写乐句还很远。我们没打算把它包装成能用的东西。 |
| LoRA 为什么有效？ | 在 8 首测试曲上配对检验显著，7/8 改善，去掉最优一首后仍有 −0.99。但只有单一种子，方差没估，这是局限。 |
| 主观听感测过吗？ | 少量试听，没有规模化评分。人耳在这个任务上分离度也不好——我们自己在盲听里都猜错过。 |
| 为什么不用 diffusion？ | 时间与显存限制，而且我们想先把"离散 Token 预测"这条线走到头，看看上限在哪。 |
| 数据是从哪下的，版权呢？ | FMA-small 是 CC-BY 4.0，允许再分发需署名；GTZAN 版权归各权利人，我们只分发预测结果不分发音频；生成音频是 MusicGen-small（CC-BY-NC 4.0），课堂用、不公开发布。 |
| 这个项目最难的地方是什么？ | 不是模型，是标签布局那件事。它不报错，只让 loss 停在一个看起来"还没训够"的值上，我们绕了三天。 |
